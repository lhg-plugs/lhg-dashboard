# lhg-db-source：数据源与指标体系设计

> 目标：让看板上的每个数字都有单位、有时间范围、有口径定义——三者缺一，数字就是玄学。
> 核心纪律：**口径没确认不画图；编造数据源字段不许。**

本 skill 是 lhg-dashboard 插件的起点：回答"看什么"的问题。
布局见 `lhg-db-layout`，图表选型见 `lhg-db-chart`，自查见 `lhg-db-audit`。

## 1. 何时使用

- 用户说"给我做个销售数据看板"，需求只有一句话时 → 必须先跑本 skill
- 已有看板但指标口径混乱、各说各话时 → 用本 skill 第 4 步重建指标体系表
- 用户已经给了明确的指标清单 → 跳过第 2-3 步，直接做第 4 步补三件套
- 只想调图表样式不想动指标 → 不用本 skill，用 `lhg-db-chart`

## 2. 输入与输出

- **输入**：一句话看板需求（可能很模糊，这是正常的）
- **输出**：`指标体系表`

| 层级 | 指标 | 单位 | 时间范围 | 口径定义 |
|---|---|---|---|---|
| 北极星 | … | … | … | … |
| 核心 | … | … | … | … |
| 明细 | … | … | … | … |

## 3. 第一步：澄清（最多 5 个问题）

### 3.1 提问原则

1. **先问"给谁看"**：看板是给老板看结论、给运营看过程，还是给自己看明细？受众决定指标粒度。
2. **再问"回答什么决策问题"**：看板不是数据的陈列柜，是决策的仪表盘。问不出决策问题，需求就没想清楚。
3. **数据源必须落地**：数据从哪来（Excel / 数据库 / 第三方后台）？谁提供？更新频率？

### 3.2 必问清单（按需取用，不超过 5 个）

1. **给谁看？**——"这个看板主要给谁看？（老板 / 运营 / 我自己）"
   → 决定指标粒度与解释成本。
2. **回答什么问题？**——"打开这个看板，你最想回答的一个决策问题是什么？"
   → 指向北极星指标；答不上来就打回，不要硬编。
3. **数据从哪来？**——"数据现在在哪？Excel 表、数据库，还是要手工录？"
   → 决定指标是否可实现；**不许编造数据源里没有的字段**。
4. **多久更新一次？**——"日更、周更，还是实时？"
   → 决定时间范围的写法与图表类型（实时数据才考虑时序细粒度）。
5. **口径谁定？**——"比如'销售额'含不含退款、含不含税，谁说了算？"
   → 找到口径的最终确认人，找不到就写"待确认"。

### 3.3 停止条件

- 5 个问题问完，或用户说"就这样，开始吧"，或北极星指标已定 → 进入第二步。
- 数据源完全没着落 → 先停下来，不要在没数据的情况下设计指标。

## 4. 第二步：定北极星指标（只定 1 个）

北极星指标是这块业务的"一句话体检"：

- 电商：日销售额 / GMV
- 内容：有效播放量 / 完播率
- SaaS：MRR / 活跃客户数

**检验标准**：这个数变了，有人知道该干什么吗？
没人行动的指标不配当北极星——它是装饰，不是仪表。

定不出来 → 说明需求还没想清楚，打回第 3 步重问，**不要硬编 10 个指标凑数**。

## 5. 第三步：分层设计指标体系

### 5.1 三层结构

| 层级 | 数量 | 作用 | 示例 |
|---|---|---|---|
| 北极星 | 1 个 | 回答"业务好不好" | 日销售额 |
| 核心 | 3-5 个 | 解释"为什么好/不好" | 转化率、客单价、访客数 |
| 明细 | 按需 | 定位"具体哪不行" | 各渠道转化率、各品类退货率 |

### 5.2 数量红线

- 一屏看板指标总数宜少不宜多，超过 15 个提醒拆看板。
- 明细指标不要一次全上：先上能定位 80% 问题的，剩下的进"二期"。

### 5.3 每个指标的三件套（铁律）

| 件套 | 要求 | 反例 |
|---|---|---|
| 单位 | 必须写：元 / % / 人 / 人次 / 天 | "销售额 1200"——1200 元还是 1200 万？ |
| 时间范围 | 必须写：2026-10-01~2026-10-11 / 近 7 天 / 本月 | "转化率 3%"——日转化还是月转化？ |
| 口径定义 | ≥10 个字：含不含退款、去重方式、统计边界 | "访客数"——按设备还是按人去重？ |

三列不许空。空着的审计规则 DB-METRIC-001/002/003 会报 blocker/warning——
那不是找茬，是救命：没有三件套的数字，开会时一定会被问住。

### 5.4 口径定义的写法模板

`[统计对象] + [统计动作] + [边界说明]`

- ✅ "当日所有渠道实付金额之和，不含退款、不含税"
- ✅ "下单人数除以访客数，访客数按设备去重"
- ❌ "销售额"（三个字，等于没写）

## 6. 第四步：输出并确认

把指标体系表给用户过目，重点确认两件事：

1. **口径定义**：同一指标不同人口径可能差一个数量级，必须用户点头。
2. **数据源可实现性**：表里的每个指标，数据源里真有对应字段吗？
   不确定的写"需对照数据源核实"，**不许编造字段名**。

**用户确认前，不许进入布局设计。**

## 7. 反模式（不要这么做）

- ❌ 一上来就画图，指标口径全靠猜——图越好看，误导性越强
- ❌ 指标体系表 20 个指标不分层——等于把 Excel 搬上了墙
- ❌ 单位写"个"、时间范围写"最近"——模糊的单位比没有更害人
- ❌ 口径定义写"销售额"三个字——审计 DB-METRIC-003 会报 warning
- ❌ 编造数据源字段（如"假设数据库里有 user_level 字段"）——这是 blocker，打回核实
- ❌ 北极星指标 3 个——北极星只能有 1 个，3 个等于没有

## 8. 自检与反馈

每次执行完本 skill，做一次轻量自检（不额外输出打扰用户）：

1. 是否问了超过 5 个澄清问题？→ 下次合并同类问题。
2. 北极星指标是 1 个吗？→ 多了就砍。
3. 每个指标都有单位/时间范围/口径定义吗？→ 跑一遍审计脚本的 DB-METRIC 系列规则。
4. 有没有编造数据源字段？→ 有就删掉，改成"需核实"。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：用"电商销售数据看板"走一遍本 skill，
  检查北极星是否唯一、三件套是否齐全、口径是否可确认。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、
  正文写清"复现输入 → 错误输出 → 期望输出"，
  提交到 https://github.com/lhg-plugs/lhg-dashboard/issues。
