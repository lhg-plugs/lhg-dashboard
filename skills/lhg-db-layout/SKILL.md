# lhg-db-layout：看板布局方法论

> 目标：一屏之内让读者 10 秒抓住结论、30 秒找到问题、1 分钟定位明细。
> 核心纪律：**一屏不超过 8 张图表；每张图表必须有标题。**

## 1. 何时使用

- 指标体系表已定，要排成一屏看板时 → 跑本 skill
- 已有看板信息过载、用户抱怨"看不过来"时 → 用本 skill 第 3、6 步重排
- 只想调单个图表的样式 → 用 `lhg-db-chart`，不用本 skill
- 指标还没定 → 先跑 `lhg-db-source`，布局不能先于指标

## 2. 输入与输出

- **输入**：指标体系表（含北极星 / 核心 / 明细三层）
- **输出**：布局说明 + 图表清单表（编号 / 标题 / 图表类型 / 数据维度 / 说明，
  列名按审计脚本约定写，可直接被审计）

## 3. 第一步：一屏三段式

一屏的标准排布，从上到下按"结论 → 趋势 → 明细"的信息优先级：

```
┌─────────────────────────────────┐
│ 顶部 KPI 卡（3-5 个）             │  ← 北极星 + 核心指标：只放数字与环比箭头
├─────────────────────────────────┤
│ 中部趋势区（2-3 张）             │  ← 折线图看走势：只放时序数据
├─────────────────────────────────┤
│ 下部明细区（2-4 张）             │  ← 条形图/表格看分布与明细
└─────────────────────────────────┘
```

### 3.1 每段的要求

- **KPI 卡**：3-5 个，大字数字 + 环比箭头（↑↓）+ 同比小字；不要放图表，卡片就是结论。
- **趋势区**：2-3 张折线图，X 轴必须是时间；超过 3 张说明趋势太多，砍。
- **明细区**：条形图看排名、表格看精确值；饼图最多 1 张，且分类 ≤6。

### 3.2 数量红线

- 一屏图表总数 **≤8 张**（审计规则 DB-LAYOUT-001）。
- 超了怎么办（三选一）：① 砍指标（最推荐）；② 拆分页（总览页 + 明细页）；
  ③ 做下钻（点击 KPI 卡跳转明细，而不是全堆在一屏）。

## 4. 第二步：每个图表定三要素

| 要素 | 要求 | 示例 |
|---|---|---|
| 标题 | "主语 + 指标 + 时间"式，不许空 | 各渠道销售额占比-10月 |
| 图表类型 | 初定，选型复核交给 lhg-db-chart | 饼图 / 折线图 / 条形图 / 表格 |
| 数据维度 | X 轴 × Y 轴，分类写清个数 | 渠道（5 个分类）× 销售额 |

**标题的反例**：

- ❌ "销售情况"（哪个销售？什么时间？）
- ❌ 空着（审计 DB-LAYOUT-002 会报 warning）
- ✅ "日销售额趋势-10月上旬"（主语日销售额 + 时间 10 月上旬）

**数据维度的写法**：分类个数必须写出来，如"渠道（8 个分类）"——
审计脚本靠这个数字判断饼图是否超标（>6 即 blocker），
写的时候自己先数一遍，超了现在就改。

## 5. 第三步：阅读动线检查

排完后做一次"视线模拟"：假设自己是目标读者，按 F 型视线（左上 → 右 → 下）走一遍：

1. 第一眼看到的 KPI 卡，能回答"业务好不好"吗？
2. 第二眼的趋势图，能回答"好/不好是从什么时候开始的"吗？
3. 第三眼的明细图，能回答"具体哪块不行"吗？
4. 有没有哪张图看了 10 秒还不知道它在讲什么？→ 标题或类型有问题，重做。

通不过 → 回到第 3 步调整，不要带着别扭的布局往下走。

## 5.5 布局模板速查（直接套用改数字）

**模板 A：经营日报（一屏）**

```
KPI 卡：日销售额 | 转化率 | 客单价 | 访客数
趋势区：日销售额趋势-近30天 | 转化率趋势-近30天
明细区：各渠道销售额排行-昨日（条形图）| Top10 商品明细（表格）
```

**模板 B：周报复盘（一屏）**

```
KPI 卡：周销售额 | 周环比 | 退货率
趋势区：日销售额趋势-本周 vs 上周（双折线，同刻度）
明细区：各品类销售额占比-本周（饼图 ≤6 分类）| 异常指标清单（表格）
```

**模板 C：明细下钻页**

```
全部用表格：支持排序与搜索，一页 20 行分页
顶部放筛选器：时间范围 / 渠道 / 品类
```

模板是起点，**必须按实际指标替换内容**，直接照抄不改数不许。

## 6. 第四步：拆分原则（图表太多时）

按以下优先级处理超标：

1. **砍**：没人行动的指标直接删（见 lhg-db-source 北极星检验标准）。
2. **拆分页**：总览页（一屏三段式）+ 明细页（表格为主），页间用导航切换。
3. **做下钻**：KPI 卡可点击，下钻看明细；一屏只保留结论层。
4. **不许**：缩小字号硬塞、加滚动条假装一屏——信息过载等于没有重点。

## 7. 移动端与投影仪检查

- **手机看**：一屏三段式在手机上变成单列，KPI 卡 2 列排布；超过 8 张图手机要滑很久，考虑只保留 KPI + 趋势。
- **投影仪看**：颜色对比度下降，浅色文字会看不见；字号不小于 14px 效果。
- **打印看**：彩色变黑白还能区分吗？不能 → 加数据标签或换纹理区分。

## 8. 反模式（不要这么做）

- ❌ 一屏 12 张图表平铺——审计 DB-LAYOUT-001 会报，看的人也记不住
- ❌ 图表标题写"销售情况"或空着——读者要猜，猜错就是你的锅
- ❌ KPI 卡里放折线图——卡片只放结论数字，趋势去趋势区
- ❌ 饼图分类 8 个还坚持用饼图——改条形图，或 Top5+其他
- ❌ 所有图表挤一屏，字小得看不见——拆分页，不许硬塞

## 9. 自检与反馈

每次执行完本 skill，做一次轻量自检（不额外输出打扰用户）：

1. 一屏图表超过 8 张了吗？→ 超了就拆。
2. 每张图表都有"主语 + 指标 + 时间"式标题吗？→ 空标题不许交付。
3. 数据维度的分类个数都写了吗？→ 没写审计脚本数不出来。
4. 阅读动线走一遍通顺吗？→ 10 秒抓不住结论就重排。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：用"电商销售数据看板，4 张图表"走一遍，
  检查三段式是否完整、标题是否规范、8 张红线是否生效。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、
  正文写清"复现输入 → 错误输出 → 期望输出"，
  提交到 https://github.com/lhg-plugs/lhg-dashboard/issues。
