# lhg-db-chart：图表选型与视觉规范

> 目标：每张图都"选型正确、刻度诚实、颜色友好"——图不好看是审美问题，图误导人是诚信问题。
> 核心纪律：**饼图分类 ≤6；折线图只画时序；双轴/3D 不许上看板。**

## 1. 何时使用

- 图表清单初定，要逐图复核选型时 → 跑本 skill
- 用户说"这张图换个好看的画法"→ 先查第 3 步选型表，好看不能代替正确
- 色板要定 → 跑第 5 步
- 指标还没定 → 先跑 `lhg-db-source`，选型不能先于指标

## 2. 输入与输出

- **输入**：图表清单（标题 / 初定类型 / 数据维度）
- **输出**：复核后的图表清单（类型定稿 + 违规项修改方案）+ 色板

## 3. 第一步：图表选型对照表

先看数据回答什么问题，再选图。**问题决定图，不是审美决定图**：

| 数据问题 | 图表类型 | 说明 |
|---|---|---|
| 构成占比（分类 ≤6） | 饼图/环形图 | 超过 6 个分类 → 改条形图，或 Top5+其他 |
| 构成占比（分类 >6） | 条形图 | 横向条形图，人眼对长度最敏感 |
| 随时间变化 | 折线图 | X 轴必须是时间；非时序数据用折线是误导 |
| 分类对比（单指标） | 柱状图/条形图 | 分类多用横向条形图，标签不打架 |
| 分类对比（双指标） | 分组柱状图 | 不许用双轴代替（见第 4 步） |
| 分布/相关 | 散点图 | 看相关性，不要连线 |
| 流程转化 | 漏斗图 | 环节 ≤6 个 |
| 精确值 | 表格 | 差异小到图上看不出时，用表格给精确值 |

### 3.1 选型三问（每张图必过）

1. 这张图回答什么问题？→ 答不上来就删图。
2. 数据维度里有时间吗？→ 没有就别用折线图（审计 DB-CHART-002 会报）。
3. 分类有几个？→ 饼图 >6 个分类直接判死刑（审计 DB-CHART-001 是 blocker）。

## 4. 第二步：四类高压线（审计会查，人工更要查）

### 4.1 饼图分类 >6（blocker）

人眼分辨扇区的能力上限约 6 个。8 个分类的饼图等于彩色披萨——
改法：Top5 + "其他"，或直接换条形图。

### 4.2 折线图画非时序数据（warning）

折线的斜率天然暗示"趋势"。拿折线画"各品类销售额对比"，
读者会下意识觉得品类之间有先后关系——这是误导。
改法：柱状图/条形图。

### 4.3 双轴图表（warning）

双轴的左右刻度可任意缩放，能制造出任何想要的"相关性"。
除非在图注中写明双轴刻度起点，否则一律拆成两张图。

### 4.4 3D 图表（warning）

3D 透视扭曲真实比例（前排扇区显大）。数据看板一律 2D，
3D 留给装饰性场合。

### 4.5 Y 轴截断（warning）

柱状图的柱长代表数值，Y 轴不从 0 开始会夸大差异。
"Y 轴从 100 开始更能看出差异"——看出的差异是假的。
改法：Y 轴从 0 开始；差异实在太小，改用表格呈现精确值。

## 5. 第三步：色板规范

### 5.1 色盲友好（审计 DB-COLOR-001 会查）

- **禁用红绿搭配**：红绿色盲是最常见的色盲类型，红/绿在他们眼里是同一色。
- 推荐色板（Okabe-Ito，色盲友好）：
  `#E69F00` `#56B4E9` `#009E73` `#0072B2` `#CC79A7` `#F0E442` `#D55E00`
- 颜色数量必须 ≥ 图表最多分类数（审计 DB-COLOR-002 会查），不够就补充。

### 5.2 颜色语义

- 一张看板只用一套色板，不要每张图换一套。
- 同一指标在不同图表中用同一颜色（如"销售额"永远是蓝色）。
- 红色只用于告警/负面，不要用来画正常数据。
- 背景用浅色，文字与背景对比度要够（投影仪上浅灰字会消失）。

### 5.3 颜色之外的区分手段

色盲用户、黑白打印、投影仪都会让颜色失效，重要区分加第二通道：

- 数据标签（直接标数字，最可靠）
- 形状/纹理（条纹、圆点）
- 图例位置固定，不要让用户满屏找图例

## 6. 第四步：图表细节清单（逐图过）

- [ ] 标题是"主语 + 指标 + 时间"式吗？
- [ ] 坐标轴有标签吗？（无标签的轴等于没画）
- [ ] 单位标了吗？（Y 轴标题含单位，如"销售额（元）"）
- [ ] 时间范围标了吗？（标题或副标题含时间）
- [ ] 数据标签开了吗？（关键数据点标数字，不要让用户目测）
- [ ] 图例不超过 6 项吗？（超了说明分类太多，回第 3 步）
- [ ] 有"数据截至 XXXX"字样吗？（看板必须标数据时效性）

## 6.5 常见图表踩坑案例（对照自查）

1. **"各渠道占比"用了 8 分类饼图** → 改法：Top5 + 其他，或换横向条形图。
2. **"各品类销售额"用了折线图** → 品类无先后，斜率是幻觉，改柱状图。
3. **"销售额 vs 转化率"用了双轴图** → 拆成两张图上下排布，X 轴对齐。
4. **"Y 轴从 100 开始"的柱状图** → 从 0 开始；差异小改用表格。
5. **红绿配色区分"达标/未达标"** → 色盲用户看到的一样，改用蓝/橙 + 数据标签。
6. **漏斗图 9 个环节** → 合并同类环节到 ≤6 个，或只展示关键转化节点。

## 7. 反模式（不要这么做）

- ❌ 8 个分类的饼图——改条形图或 Top5+其他
- ❌ 折线图画品类对比——斜率暗示了不存在的趋势
- ❌ 双轴图展示"销售额与转化率的相关性"——刻度一缩放，什么相关性都有
- ❌ 3D 饼图——前排扇区显大，比例全是假的
- ❌ Y 轴从 100 开始的柱状图——夸大差异，误导决策
- ❌ 红绿配色——色盲用户看到的是同一坨颜色
- ❌ 坐标轴无标签、无单位——读者要猜，猜错就是误导

## 8. 自检与反馈

每次执行完本 skill，做一次轻量自检（不额外输出打扰用户）：

1. 每张图都过了"选型三问"吗？→ 没过就改类型。
2. 四类高压线还有残留吗？→ 跑一遍审计脚本复核。
3. 色板是色盲友好的吗？颜色数够吗？→ 不够就补。
4. 图表细节清单 7 项都过了吗？→ 缺项补上。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：拿 fixtures/dashboard-bad/spec.md 跑一遍，
  检查 12 条规则是否全命中、修改方案是否可执行。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、
  正文写清"复现输入 → 错误输出 → 期望输出"，
  提交到 https://github.com/lhg-plugs/lhg-dashboard/issues。
