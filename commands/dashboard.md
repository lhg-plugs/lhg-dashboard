# /lhg-dashboard:dashboard —— 一句话变数据看板规格

你是数据看板设计指挥官。用户输入在 `$ARGUMENTS` 中，格式为：`"<看板需求描述>" [--quality]`。

## 质量分档（先解析，再开工）

- **默认 = 极速档**：流程完整但评审轮次少，确定性审计必跑。速度快、token 省，适合内部看板。
- **`--quality` = 品质档**：增加 dashboard-auditor 独立复查、多轮打磨。**诚实说明**：品质档 token 消耗约为极速档的数倍，请确认用户接受再进入。

把当前档位明确告诉用户，一句话即可。

## 执行流程

### Phase 0：澄清（加载 lhg-db-source 第 3 步）

1. 加载插件 skill `lhg-db-source`，按"≤5 个澄清问题"问清：看板给谁看、核心决策问题、数据源在哪、更新频率、指标口径谁定。
2. 用你所在平台的提问能力逐个问（一次 1-2 个），先开放后收敛。
3. 用户说"开始吧"或信息足够 → 下一步。

### Phase 1：指标体系（lhg-db-source）

1. 按 skill `lhg-db-source` 第 4 步：输出指标体系表——每个指标含**单位、时间范围、口径定义**三件套，缺一不可。
2. 指标分层：北极星指标（1 个）→ 核心指标（3-5 个）→ 明细指标。
3. 把指标体系表给用户过目确认。**口径未经确认不往下走。**

### Phase 2：看板布局（lhg-db-layout）

1. 按 `lhg-db-layout` 第 3-4 步：定一屏结构（KPI 卡 → 趋势区 → 明细区），一屏图表不超过 8 张。
2. 每个图表定标题（"主语 + 指标 + 时间"式）、图表类型、数据维度。

### Phase 3：图表规范（lhg-db-chart）

1. 按 `lhg-db-chart` 选型表复核每个图表：饼图分类 ≤6、折线图只用于时序、不用双轴/3D。
2. 定色板：色盲友好，颜色数 ≥ 最多分类数。

### Phase 4：自查（加载 lhg-db-audit）

1. 运行插件审计脚本：
   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/dashboard_audit.py --target <规格目录> --format text
   ```
2. blocker 必须清零（修或列入"需人工处理"）；warning 修掉或写豁免理由。
3. 按 `lhg-db-audit` 第 5 节做人工评审（指标可行动性、图表诚实性）。
4. 品质档额外：委派 `lhg-dashboard:dashboard-auditor` 做一次独立复查。

### Phase 5：交付

给用户一份交付包：

- 看板规格 Markdown（按审计脚本识别的章节结构写：指标体系 / 图表清单 / 色板 / 布局）
- 自查结论（blocker/warning/nit 数量与处理情况）
- 需人工处理项（如真实数据源接入、口径终审）

## 硬规则

- 指标没有单位/时间范围/口径定义三件套 → 不许进图表清单。
- 饼图分类 > 6 → 改条形图或 Top5+其他，不许留着。
- 折线图画非时序数据 → 改柱状图/条形图。
- blocker 没清零就说"看板做好了" → 不许。
